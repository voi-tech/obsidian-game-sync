# Canonical sync architecture

The production sync path is provider-neutral. Legacy state/service code is
retained only at compatibility boundaries that have not yet received a
canonical replacement.

```text
GameProvider
  -> CanonicalLibrarySnapshot
  -> CanonicalGame[]
  -> canonical matcher
  -> CanonicalSyncPlan
  -> CanonicalVaultWriter
```

## Provider boundary

`GameProvider` exposes capabilities, diagnostics and a `getSnapshot()` method.
A snapshot is `complete`, `partial` or `failed`. Only a complete snapshot can
produce a plan or be written to the vault. `getLibrary()` remains available as
a convenience accessor, but callers that may write must use the snapshot
contract.

`GameTrackCsvProvider`, `SteamLibraryProvider` and
`PlayStationLibraryProvider` are the library implementations. The production
GameTrack transport is a read-only user-selected ZIP parsed in memory. SQLite
and private-container access are not imported by the standard runtime.

## CanonicalGame

`CanonicalGame` contains identity, metadata, normalized platform presence,
playtime observations, achievement summaries and provenance. Its canonical
playtime unit is minutes. Platform observations are never silently summed with
the GameTrack aggregate.

Identity keeps both `externalIds.gametrack` and `externalIds.igdb`. The
canonical key generated by GameTrack is `gametrack:<ZID>`. Existing note
matching may retain an older `game-sync-id` while adding the new stable IDs.

## Matching

`matchCanonicalVaultNote()` uses this order:

1. explicit canonical mapping;
2. existing `game-sync-id`;
3. IGDB ID;
4. GameTrack ID;
5. known legacy Steam/PlayStation identifiers;
6. title and release-year fallback.

Stable identifiers are explicit matches. Title fallback is review-only, and
ambiguous candidates are never auto-merged.

## Property ownership and writer

`buildCanonicalManagedProperties()` projects only provider-managed values. The
canonical writer updates those values and preserves user-managed, unknown and
custom properties as well as the Markdown body. Undefined provider values are
omitted; they do not become zero, `false` or a deletion. Existing legacy
provider properties are preserved rather than rewritten by this path.

The current canonical writer handles summary properties only. Detailed
achievement blocks and full template parity remain legacy/next-phase work.

## Planner and state

`planCanonicalSync()` returns neutral create/update/unchanged/conflict statuses
and operations. It performs no vault writes. `canonicalGameFingerprint()` covers
provider-managed output data and excludes user-owned properties. The plan
revision is based on canonical source fingerprints.

`CanonicalSyncService` composes provider, planner and writer. It refuses to
write partial or failed snapshots. Runtime composition accepts an optional
canonical provider injection so a supported desktop host can register it
lazily without pulling Node code into the mobile bundle.

Optional Steam and PlayStation enrichers run after the library snapshot and
before matching/planning. They patch only existing canonical games, preserve
source provenance and cannot add library membership. Their failure is reported
as a warning while the complete base snapshot may still be planned.

## Legacy compatibility

The existing `SyncService` and legacy provider models remain for state
readers, history and match-management compatibility. Explicitly selected
Steam, PlayStation and GameTrack library sources use the canonical service;
the legacy path is retained only when old combined state cannot yet be
represented safely by the canonical runtime.

## Runtime requirements and limitations

- GameTrack official ZIP export: supported manual transport; source selection
  is user-controlled and the archive is never modified.
- Direct GameTrack SQLite: not included in the standard runtime.
- There is no background re-import of a selected GameTrack export or full
  achievement catalogue. A background run may refresh enabled enrichers
  against the last imported GameTrack snapshot.

## Scheduler boundary

The background scheduler consumes the neutral `SyncExecutor` contract from
`src/sync/background-executor.ts`. Composition adapts the active canonical or
legacy service at the boundary; the scheduler does not inspect Steam,
PlayStation, GameTrack, SQLite or legacy operation shapes. Preview and apply
share the same opaque prepared plan, and a shared concurrency guard prevents
manual and scheduled operations from overlapping. Partial/failed snapshots
and unapproved GameTrack background runs are write-blocked.
